Synthetic data. Every record here is computer generated by this repository; none of it comes from a real patient. The extraction backend is a configurable rule and lexicon baseline, not a trained clinical NLP model, and coded terms in the catalogue are illustrative placeholders rather than licensed dictionary content.

Mucosal involvement can live in a standard qualifier, a linked skin-and-mucosa form, the investigator's own words, a comment record — or nowhere. Which one applies is a per-study collection decision, and the route is part of the fact: every value below says which variable it came from and by which method.

Assertion and availability are separate fields, and never merged. Assertion is what the source said — present, absent, uncertain. Availability is whether it said anything at all. A record with assertion=absent is somebody who was examined and found clear: a non_case, in the denominator. A record with availability=not_collected is silence, and belongs in neither the numerator nor the denominator. Collapsing them biases every rate.

Materiality, declared in advance

The thresholds below live in ablation.py and were written before the numbers were seen, so the decision cannot be talked into existence afterwards.

One profile records mucosal involvement in a structured variable and in the investigator's own words. Masking the structured value gives a real evaluation set on data nobody hand-annotated. What is compared is the assertion, not just the value: an extractor that turned every documented "no" into silence would score perfectly on values while destroying the denominator.

By assertion class

Broken out because the classes fail differently, and the one that decides the denominator is also the rarest and the easiest to lose in an average.

Calibration

A stated confidence of 0.8 should be right about eight times in ten. Every phenotype definition here thresholds on this number, so overconfidence turns into cases nobody can defend.

Method

  1. mask the structured variable from the extractor
  2. run the model path over the text alone
  3. normalize both sides to the same value space
  4. compare the extracted assertion against the masked one

Adjudication queue

Disagreements, low-confidence predictions, and a random sample of agreements. The sample is not optional: without it you only ever inspect failures and can never estimate the comparator's own error rate — which, given caveat 1, is the number that decides how much any of this is worth.

Four verdicts. non_case means somebody looked and the answer was no — that subject is in the denominator. not_ascertainable means nobody can tell, not the system and not a reviewer, so the subject is in neither the numerator nor the denominator and the ascertainable fraction says how many were lost that way.

Executed, not textual: both versions run against the same snapshot. A scope is required — this is for evidence reuse within a stated question, not for sweeping a programme to audit past choices.

Cohort membership is decided by normalized values and a definition's verdict — no embedding is consulted for it. Assertion and availability are separate filters here too, so "documented negatives" and "never asked" cannot be requested as one population. Discovery is where free-text search earns its place, and everything it returns is a candidate.

The agent binds an existing definition version and runs it through typed, permissioned tools. It computes nothing itself: there is no SQL surface and no tool that writes to a source record. It never invents phenotype parameters — a question implying a different window or assertion is a conflict for a person to settle, not a parameter to override. There is no approval click; what makes a number checkable is the trace returned with it.
